# Adminkatest — панель администрирования

Локальный прототип панели на Python standard library, SQLite, HTML, CSS и JavaScript. Backend из `app.py` обслуживает страницы админки и JSON API на одном origin; браузерный mock заменён на запросы к серверу. Состояние хранится в SQLite и сохраняется после перезапуска.

> **Важное ограничение:** backend изолирован от рабочей БД площадки и использует свою локальную базу. Данные, создаваемые при первом старте, помечены смыслом демо и не являются данными реальных пользователей, аукционов или финансов. Чтобы подключить рабочую площадку, нужны её схема/API, правила доступа и согласованный контракт. Не запускайте прототип в интернете.

## Запуск (Windows PowerShell)

Требуется Python 3.11+:

```powershell
$env:ADMIN_USERNAME = "super"
$env:ADMIN_EMAIL = "super@example.test"
$env:ADMIN_PASSWORD = "replace-with-a-unique-password-of-12-chars-or-more"
py -3 app.py
```

Откройте <http://127.0.0.1:7070/admin/>. При первом запуске создаются SQLite база `data/admin.sqlite3`, супер-администратор и небольшие демонстрационные записи. Начальный пароль задаётся только через `ADMIN_PASSWORD`; тестовые пароли, открытые в коде или передаваемые в браузерные хранилища, не используются.

В `APP_ENV=development` код одноразового входа выводится **только в консоль процесса backend**. Для отправки OTP по email настройте SMTP:

```powershell
$env:SMTP_HOST = "smtp.example.test"
$env:SMTP_PORT = "587"
$env:SMTP_USER = "..."
$env:SMTP_PASSWORD = "..."
$env:SMTP_FROM = "admin@example.test"
py -3 app.py
```

Реальную массовую рассылку можно выполнять только после SMTP-настройки; получателями являются записи со статусом активной подписки. Без SMTP API явно отказывает в отправке.

## Разделы и структура интерфейса

Категории отделены страницами, локальными CSS и JS в отдельных каталогах:

- `admin/support/` — поддержка и жалобы;
- `admin/info/` — пользователи, лоты, магазины;
- `admin/content/` — баннеры, новости и курсы;
- `admin/finance/` — продвижение, прибыль, отключённые возвраты;
- `admin/analytics/` — статистика и транзакции;
- `admin/system/` — подписчики, аудит, администраторы и служебные инструменты.

Общие стили и логика переиспользуются из `admin/css/` и `admin/js/`. Страницы категорий имеют собственные `index.html`, `style.css` и `app.js`.

Обычная роль ограничена разделами пользователей, лотов, новостей, жалоб, саппорта и магазинов. Суперадминистратору доступны остальные модули. Пользовательская карточка и счётчики активности загружаются отдельным запросом при выборе пользователя; поля поиска пользователей переключаются между ником, email, ID и названием магазина. Новости принимают HTML как содержимое и уменьшают загружаемое изображение в браузере перед сохранением. Курсы валют редактируются вручную; источник актуальных курсов не подключён.

До подключения источника финансовых данных прибыль и обороты отображаются как ноль. Перед входом в раздел прибыли сервер повторно проверяет пароль суперадминистратора. Возвраты недоступны.

## Хранение и безопасность

- Пароли администраторов хранятся как salted `scrypt` hashes; пароль не записывается в TXT или журнал аудита.
- Вход использует HttpOnly/SameSite cookie, CSRF-токен, одноразовый код и блокировку частых неудачных попыток.
- Все CRUD-изменения проходят через сервер, проверку прав и записываются в SQLite audit; отдельный `data/admin-logs/admin-<id>.txt` создаётся для каждого администратора. Скачать журнал может только супер-администратор.
- Данные хранятся в `data/`, которая не раздаётся статическим сервером. Не добавляйте базу и логи в Git.
- По умолчанию сервер слушает только `127.0.0.1`. Для любой внешней публикации необходимы HTTPS/reverse proxy, `COOKIE_SECURE=1`, production WSGI/ASGI сервер, резервное копирование, мониторинг и независимая проверка безопасности.

Переменные окружения:

| Переменная | Назначение |
|---|---|
| `ADMIN_HOST` | Адрес сервера; по умолчанию `127.0.0.1` |
| `ADMIN_PORT` | Порт; по умолчанию `7070` |
| `ADMIN_DATA_DIR` | Каталог базы и журналов; по умолчанию `./data` |
| `ADMIN_DB` | Отдельный путь к SQLite |
| `ADMIN_USERNAME`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` | Учётная запись, создаваемая только при пустой таблице администраторов |
| `SESSION_MINUTES` | Таймаут бездействия, 30 минут по умолчанию |
| `OTP_TTL_SECONDS` | Срок жизни OTP, 600 секунд по умолчанию |
| `APP_ENV` | В разработке OTP виден в консоли; в иных режимах требуется SMTP |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`, `SMTP_SSL` | Параметры почты |
| `COOKIE_SECURE` | Установить `1` для Secure cookie за HTTPS |

## Присланный фрагмент авторизации

Функция `pushDataToServer(mail, pass)` из присланного текста не подключена. Она отправляла пароль пользователя стороннему адресу по незашифрованному HTTP. Принимать и пересылать пароли пользователей через этот код небезопасно. Реальную авторизацию пользователей следует выполнять только на доверенном backend площадки, никогда не логировать пароль и не передавать его в админскую панель.

## Ограничения прототипа

1. Реальная база площадки, внешний поиск, профильные данные и аудит действий пользователей не подключены.
2. Реальные суммы по рекламе, лотам, доступным средствам и транзакциям не интегрированы; денежные расчёты остаются нулевыми.
3. Курс валют вручную вводится администратором, внешний провайдер не подключён.
4. HTML новостей сохраняется, но безопасный публичный рендеринг/санитизация и публикация на витрине не реализованы.
5. Backend на `http.server` предназначен только для локального прототипа, не для production.

Основные базы контента и подключение к ним описаны в [DATABASES.md](DATABASES.md).
