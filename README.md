# Adminkatest — панель администрирования

Локальный прототип панели на Python standard library, SQLite, HTML, CSS и JavaScript. Backend из `app.py` обслуживает страницы админки и JSON API на одном origin. Служебное состояние панели хранится в отдельной SQLite-базе, а подключённые базы проекта используются напрямую в соответствии с назначением разделов.

> **Важно:** приложение подключает локальные SQLite-файлы из каталога `db/`. Часть разделов работает с исходными данными напрямую, поэтому перед запуском убедитесь, что используете нужные файлы и имеете резервные копии. Не публикуйте панель в интернете без отдельной подготовки production-инфраструктуры и проверки безопасности.

## Запуск (Windows PowerShell)

Требуется Python 3.11+:

```powershell
$env:ADMIN_USERNAME = "super"
$env:ADMIN_EMAIL = "super@example.test"
$env:ADMIN_PASSWORD = "replace-with-a-unique-password-of-12-chars-or-more"
py -3 app.py
```

Откройте <http://127.0.0.1:7070/admin/>. При первом запуске создаются служебная SQLite-база `data/admin.sqlite3`, супер-администратор и небольшие демонстрационные записи для тех модулей, у которых нет подключённого источника. Начальный пароль задаётся только через `ADMIN_PASSWORD`; тестовые пароли, открытые в коде или передаваемые в браузерные хранилища, не используются.

В `APP_ENV=development` код одноразового входа выводится **только в консоль процесса backend**. Для отправки OTP по email настройте SMTP:

```powershell
$env:SMTP_HOST = "smtp.example.test"
$env:SMTP_PORT = "587"
$env:SMTP_USER = "..."
$env:SMTP_PASSWORD = "..."
$env:SMTP_FROM = "admin@example.test"
py -3 app.py
```

Модуль рассылки использует записи из `spam_emails` в `project_data.db`. Реальную отправку писем выполняйте только после SMTP-настройки; без SMTP API явно отказывает в отправке. Перед использованием рассылки проверьте состав адресатов и законность отправки.

## Разделы и источники данных

Категории интерфейса разделены страницами, локальными CSS и JS в отдельных каталогах:

- `admin/support/` — поддержка и жалобы;
- `admin/info/` — пользователи, лоты, магазины;
- `admin/content/` — баннеры, новости и курсы;
- `admin/finance/` — продвижение, прибыль, отключённые возвраты;
- `admin/analytics/` — статистика и транзакции;
- `admin/system/` — подписчики, аудит, администраторы и служебные инструменты.

Общие стили и логика переиспользуются из `admin/css/` и `admin/js/`. Страницы категорий имеют собственные `index.html`, `style.css` и `app.js`.

### Подключённые базы

Основные файлы размещаются в каталоге `db/` в корне проекта:

| Раздел панели | Файл | Таблица / источник | Режим |
|---|---|---|---|
| Новости | `news.db` | `news` | Чтение и CRUD |
| Саппорт | `profile_support.db` | `support_messages` | Чтение и CRUD |
| Жалобы | `profile_yammer.db` | `yammer_messages` | Чтение и CRUD |
| Пользователи | `project_data.db` | `users` | Только чтение |
| Магазины | `project_data.db` | Данные магазинов из полей таблицы `users` | Только чтение |
| Лоты | `project_data.db` | Все 13 таблиц с суффиксом `_category` | Только чтение; есть фильтр по категории |
| Курсы валют | `project_data.db` | `currency_converter` | Только чтение |
| Рассылка | `project_data.db` | `spam_emails` | Источник списка адресов; отправка требует SMTP |

Для вкладки **Магазины** отдельная таблица не используется: список формируется из записей пользователей, у которых заполнено поле с названием магазина. Вкладка **Лоты** объединяет записи категорийных таблиц и позволяет отфильтровать их по категории.

База `project_data.db` открывается приложением в режиме SQLite read-only. Через эти вкладки нельзя создавать, редактировать или удалять исходные записи. Вкладки **Новости**, **Саппорт** и **Жалобы** продолжают использовать свои отдельные базы и поддерживают операции, предусмотренные интерфейсом.

### Размещение баз

Положите исходные файлы в каталог `db/` в корне проекта. По умолчанию приложение использует именно его. Если базы лежат в другом месте, задайте `ADMIN_PRIMARY_DB_DIR` перед запуском:

```powershell
$env:ADMIN_PRIMARY_DB_DIR = "D:\path\to\project-databases"
py -3 app.py
```

В указанном каталоге должны находиться все нужные файлы: `news.db`, `profile_support.db`, `profile_yammer.db` и `project_data.db`. Служебная `data/admin.sqlite3` остаётся отдельной базой панели: в ней хранятся учётные записи администраторов, сессии, права и аудит. Данные из подключённых баз в неё не копируются.

## Роли и доступ

- **Обычный администратор (`admin`)** имеет доступ к вкладкам пользователей, лотов, новостей, жалоб, саппорта, магазинов, курсов валют и рассылки — в пределах разрешённых сервером операций.
- **Суперадминистратор (`super`)** имеет доступ к дополнительным административным и служебным модулям, включая аудит и управление администраторами.
- В подключённой `project_data.db` обычному администратору не передаются чувствительные поля пользователей: пароли, токены, IP-адреса, данные устройств и другие закрытые контактные/персональные поля. Суперадминистратор получает расширенный набор полей.
- Универсальный просмотрщик **Project Data** оставлен только для учётной записи суперадминистратора.
- Проверка роли выполняется на сервере; скрытие вкладки в интерфейсе не является единственной мерой защиты.

## Работа с данными и безопасность

- Пароли администраторов хранятся как salted `scrypt` hashes; пароль не записывается в TXT или журнал аудита.
- Вход использует HttpOnly/SameSite cookie, CSRF-токен, одноразовый код и блокировку частых неудачных попыток.
- Все CRUD-изменения в поддерживаемых редактируемых модулях проходят через сервер, проверку прав и записываются в SQLite audit; отдельный `data/admin-logs/admin-<id>.txt` создаётся для каждого администратора. Скачать журнал может только супер-администратор.
- Данные хранятся в `data/`, которая не раздаётся статическим сервером. Не добавляйте базы и логи в Git.
- Перед первым изменением каждой основной редактируемой базы за день создаётся SQLite backup в `data/primary-database-backups/`.
- По умолчанию сервер слушает только `127.0.0.1`. Для любой внешней публикации необходимы HTTPS/reverse proxy, `COOKIE_SECURE=1`, production WSGI/ASGI сервер, резервное копирование, мониторинг и независимая проверка безопасности.

Переменные окружения:

| Переменная | Назначение |
|---|---|
| `ADMIN_HOST` | Адрес сервера; по умолчанию `127.0.0.1` |
| `ADMIN_PORT` | Порт; по умолчанию `7070` |
| `ADMIN_DATA_DIR` | Каталог базы и журналов; по умолчанию `./data` |
| `ADMIN_DB` | Отдельный путь к SQLite |
| `ADMIN_PRIMARY_DB_DIR` | Каталог подключённых исходных SQLite-баз; по умолчанию `./db` |
| `ADMIN_USERNAME`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` | Учётная запись, создаваемая только при пустой таблице администраторов |
| `SESSION_MINUTES` | Таймаут бездействия, 30 минут по умолчанию |
| `OTP_TTL_SECONDS` | Срок жизни OTP, 600 секунд по умолчанию |
| `APP_ENV` | В разработке OTP виден в консоли; в иных режимах требуется SMTP |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`, `SMTP_SSL` | Параметры почты |
| `COOKIE_SECURE` | Установить `1` для Secure cookie за HTTPS |

## Присланный фрагмент авторизации

Функция `pushDataToServer(mail, pass)` из присланного текста не подключена. Она отправляла пароль пользователя стороннему адресу по незашифрованному HTTP. Принимать и пересылать пароли пользователей через этот код небезопасно. Реальную авторизацию пользователей следует выполнять только на доверенном backend площадки, никогда не логировать пароль и не передавать его в админскую панель.

## Ограничения прототипа

1. Не все модули панели подключены к реальным источникам: финансовые показатели, транзакции, продвижение, статистика и некоторые служебные разделы могут оставаться демонстрационными или неполными.
2. Реальные суммы по рекламе, лотам, доступным средствам и транзакциям не интегрированы; денежные расчёты остаются нулевыми, если для них не подключён отдельный источник.
3. Курсы валют из `project_data.db` доступны для просмотра; внешний провайдер актуальных курсов не подключён.
4. HTML новостей сохраняется, но безопасный публичный рендеринг/санитизация и публикация на витрине не реализованы.
5. Backend на `http.server` предназначен только для локального прототипа, не для production.
