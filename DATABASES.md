# Основные базы данных проекта

Админ-панель использует четыре SQLite-файла в каталоге `db/`. Три базы обслуживают редактируемые разделы контента, а `project_data.db` подключена к информационным вкладкам в режиме только чтения.

| Раздел панели | Файл | Таблица / источник | Режим |
|---|---|---|---|
| Новости | news.db | news | Чтение и CRUD |
| Саппорт | profile_support.db | support_messages | Чтение и CRUD |
| Жалобы | profile_yammer.db | yammer_messages | Чтение и CRUD |
| Пользователи | project_data.db | users | Только чтение |
| Магазины | project_data.db | Поля магазина в users | Только чтение |
| Лоты | project_data.db | 13 таблиц с суффиксом _category | Только чтение, с фильтром по категории |
| Курсы валют | project_data.db | currency_converter | Только чтение |
| Рассылка | project_data.db | spam_emails | Источник списка адресов; отправка требует SMTP |

## Размещение

Положите исходные файлы в каталог `db/` в корне проекта. По умолчанию приложение использует именно его. Если базы лежат в другом месте, задайте ADMIN_PRIMARY_DB_DIR перед запуском:

```powershell
$env:ADMIN_PRIMARY_DB_DIR = "D:\path\to\project-databases"
py -3 app.py
```

В каталоге должны находиться базы, которые нужны используемым разделам. Служебная `data/admin.sqlite3` остаётся отдельной базой панели: в ней хранятся учётные записи администраторов, сессии, права и аудит. Контентные записи в неё не копируются.

## Работа с редактируемыми базами

- В разделах новостей, саппорта и жалоб используются исходные названия и типы колонок соответствующих таблиц.
- Поиск, просмотр страниц, создание, редактирование и удаление выполняются непосредственно в основной SQLite-базе.
- Первичный ключ id генерируется самой SQLite и не редактируется из формы.
- Файлы в поле proof можно заменить загрузкой нового файла. Если файл не выбран, прежнее вложение сохраняется.
- Содержимое вложений не выводится в таблицу: показывается только наличие и размер.
- Все изменения требуют разрешения на соответствующий раздел, CSRF-проверки и записываются в журнал аудита admin.sqlite3.
- Перед первым изменением каждой основной редактируемой базы за день создаётся SQLite backup в data/primary-database-backups/.

## Доступ к project_data.db

- База открывается приложением в SQLite read-only режиме; через админ-панель её исходные записи не изменяются.
- Магазины формируются из таблицы users по заполненному полю названия магазина.
- Лоты собираются из всех 13 таблиц, имена которых заканчиваются на _category; интерфейс предоставляет фильтр по категории.
- Курсы читаются из currency_converter, а список адресов рассылки — из spam_emails.
- Обычной роли admin сервер не передаёт пароли, токены, IP-адреса, данные устройств и другие закрытые персональные поля. Роль super получает расширенный набор данных.
- Универсальный просмотрщик Project Data доступен только суперадминистратору.

## Важно для Git

Каталог `db/` намеренно исключён из Git: базы могут содержать персональные данные пользователей и вложения. Не публикуйте эти файлы в открытом репозитории. При развёртывании приложения передайте нужные базы в `db/` защищённым способом. Автоматической миграции или изменения структуры таблиц приложение не выполняет.
