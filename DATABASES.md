# Основные базы данных проекта

Админ-панель работает с тремя основными SQLite-базами проекта. Это не демо-раздел и не копии: существующие пункты меню **Новости**, **Саппорт** и **Жалобы** читают и изменяют соответствующие файлы напрямую.

| Раздел панели | Файл | Таблица |
|---|---|---|
| Новости | news.db | news |
| Саппорт | profile_support.db | support_messages |
| Жалобы | profile_yammer.db | yammer_messages |

## Размещение

Положите исходные файлы в каталог db/ в корне проекта. По умолчанию приложение использует именно его. Если базы лежат в другом месте, задайте ADMIN_PRIMARY_DB_DIR перед запуском:

    $env:ADMIN_PRIMARY_DB_DIR = "D:\path\to\project-databases"
    py -3 app.py

data/admin.sqlite3 остаётся отдельной служебной базой панели: в ней хранятся учётные записи администраторов, сессии, права и аудит. Контентные записи не копируются в неё.

## Работа с данными

- В каждом обычном разделе используются исходные названия и типы колонок соответствующей таблицы.
- Поиск, просмотр страниц, создание, редактирование и удаление выполняются непосредственно в основной SQLite-базе.
- Первичный ключ id генерируется самой SQLite и не редактируется из формы.
- Файлы в поле proof можно заменить загрузкой нового файла. Если файл не выбран, прежнее вложение сохраняется.
- Содержимое вложений не выводится в таблицу: показывается только наличие и размер.
- Все изменения требуют обычных прав на соответствующий раздел, CSRF-проверки и записываются в журнал аудита admin.sqlite3.
- Перед первым изменением каждой основной базы за день создаётся SQLite backup в data/primary-database-backups/.

## Важно для Git

Каталог db/ намеренно исключён из Git: базы могут содержать персональные данные пользователей и вложения. Не публикуйте эти файлы в открытом репозитории. При развёртывании приложения передайте три базы в db/ защищённым способом. Автоматической миграции или изменения структуры таблиц приложение не выполняет.
